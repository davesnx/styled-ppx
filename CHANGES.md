# Changes

## 0.62.0

- [BREAKING] A block's interpolating declarations now bundle into one shared class only when they interpolate the SAME `$(name)` source path (transitively, same union-find technique the leaf-overlap grouping already uses for shorthands), instead of whenever two or more of them merely both happen to interpolate. `color: $(a); background-color: $(b);` used to force `a` and `b` into one opaque `_in_` bundle for no reason neither value needed; both now mint their own real, slot-keyed `_a_` class and `CSS.merge` resolves each independently. `$(a)` used twice in one block - base and `:hover`, or any other combination of variants - still shares exactly one variable and one inline custom property, same as before: the invariant bundling exists for is unchanged, only narrowed to declarations that actually need it. A declaration whose path no sibling shares still joins the existing leaf-overlap grouping with its block's other declarations first, unaffected - this only changes which SINGLETON interpolating atoms end up sharing a class (@davesnx)
- [BREAKING] Class-name prefixes are now longer and self-delimiting: atom `a-` -> `_a_`, interpolation bundle `in-` -> `_in_`, identity `id-` -> `_id_`, `@keyframes` `k-` -> `_k_`, each followed directly by its fields/hash with no separately-concatenated `-`. `Merge_key` (native and melange) now recognizes only `_a_` as an atom prefix; a hand-written class that merely starts with the old `a-` shape, such as `a-header`, is no longer misread as an atom by `CSS.merge` and now survives untouched. The same documented ambiguity (a hand-written class whose body happens to land on one of the six lengths a real atom can have) persists at the new prefix, just far less likely by accident: a hand-written class now needs to start with the exact `_a_` sequence to collide at all. Every existing class, identity and keyframe name changes; a stylesheet or code that hard-codes one must follow (@davesnx)
- [BREAKING] A block with TWO OR MORE declarations that carry a `$(...)` value interpolation now mints one shared `in-<hash>` class for all of them instead of `a-<hash>` per declaration (same murmur2 digest of their concatenated content, only the prefix changes; the `var(--...)` custom-property name each one sets is unaffected). A block with exactly ONE interpolating declaration is unaffected by this bundling and keeps its own real, slot-keyed `a-` class (see below). `CSS.merge` (below) recognizes an interpolation-bundled atom this way - several different declarations from one binding legitimately sharing one class, by design - and never drops it or lets it drop another atom, and `styled-ppx.generate`'s atom-class collision check (below) skips it, since two different bundle bodies sharing a class is not a collision (@davesnx)
- [FEATURE] `styled-ppx.generate` now errors when two different, non-bundle atoms (`a-` classes) mint the same class name but render different CSS - a value-hash collision - the same way it already errors on a `id-` identity collision. `in-` (interpolation-bundle) classes are exempt: sharing one class across different bundle bodies is expected there, not a collision (@davesnx)
- [BREAKING] Two declarations in one block now mint ONE atom, declarations in author order, when their covered leaf properties overlap - taken transitively - instead of one atom per declaration. `margin: 10px; margin-top: 0;` is one atom (margin's full leaf set includes margin-top), so the final declaration in a mixed shorthand/longhand group reliably resets the earlier ones by source order, not by where two independently-hashed atoms happen to land in the generated stylesheet. This extends the existing same-property grouping (`display: -webkit-box; display: flex` already grouped into one atom, a same-property repeat overlapping itself trivially). Sharing a property family alone is not enough: `padding-left: 0; padding-right: 0;` stay two atoms, since padding-left and padding-right cover disjoint leaves - merging them would make `CSS.merge` (below) unable to drop just the overlapping side (@davesnx)
- [BREAKING] Non-bundle class names are now `a-<context?><family><mask?><value>`: a fixed-width context hash (present only under a real selector/at-rule, or when the declaration carries `!important`), a 2-character property-family id from a fixed table, an optional mask of which of the family's longhands the atom covers, and a value hash unique only within that (context, family[, mask]) bucket, not globally - shorter than the previous plain content hash for the common case. This is what `CSS.merge` (below) parses at runtime to decide which classes to drop, with no shorthand table (@davesnx)
- [FEATURE] `CSS.merge(a, b)` (native and melange) now drops a class of `a` when a class of `b` covers the same slot - same context, same property family, `a`'s longhands a subset of `b`'s - instead of concatenating both class strings unconditionally. This fixes a real bug: under content-hash dedup, an atom two components both use can be minted first by either one, and the browser's cascade then picks whichever copy's rule landed first in the generated stylesheet - independent of which `CSS.merge` call actually meant to win. `!important` needs no separate check (it is folded into the context, so a plain declaration and its `!important` twin never remove each other); a bundle, an identity class, a `label:<binding>` marker, and any class this pipeline didn't mint are never dropped and never drop anything else. Accepted limit, pinned by tests: `merge(shorthand, one-of-its-own-longhands)` keeps both classes, since a lone longhand's mask is never a superset of the shorthand's full mask - which one wins still depends on stylesheet position in that one direction (@davesnx)
- [FIX] Resolve a `[%css]` selector's `$(binding)`/`&.$(binding)` reference to the referenced binding's identity class BEFORE atomizing, not after. An atom's class name and `Slot_key` context both hash the rendered selector text; hashing it before resolution left the literal `$(binding)` marker in that text, so two files using the same local binding name in the same selector shape (e.g. `& > div:not(:last-child).$(row)`, with each file's own, differently-defined `row`) minted the SAME atom class even though `row` resolves to a different `id-` class per file - a real collision `styled-ppx.generate`'s atom-class collision check (above) then correctly rejected. A same-reference case (two files, or a cross-module `$(Module.binding)`, naming the exact same binding) still dedups to one class, unaffected (@davesnx)
- [FIX] A block with exactly ONE `$(...)`-interpolating declaration no longer bundles: it mints its own real, slot-keyed `a-` class - same path a static atom uses - so `CSS.merge` (above) can resolve it like any other atom instead of treating it as an opaque, always-kept `in-` blob. Bundling still applies, unchanged, to a block with two or more interpolating declarations (typically the same value reused across `base`/`:hover`/`@media` variants, which still needs one shared custom-property namespace). This fixes two real cases `CSS.merge` previously couldn't touch: two same-property, single-declaration interpolated overrides (e.g. `background-color: $(accent)` vs `background-color: $(bg)`), and a single interpolated declaration overridden by a later static one of the same property (e.g. `padding-top: $(gap)` vs a later `padding-top: 0`) - both used to keep both classes and depend on stylesheet position; both now resolve by merge-call argument order like any other atom. `Slot_key.t.bundle` no longer self-detects from a declaration's own interpolation (a per-atom fact it could get wrong, since bundle-hood depends on how many OTHER declarations share the block); it is always `false` from `Slot_key.of_atom` now, since a genuine bundle's class is minted directly and never goes through `Slot_key`/`Class_format.slot_class` (@davesnx)
- [BREAKING] `styled-ppx.generate` now wraps every style rule it emits - an atom (`a-`/`in-` class) or a `[%styled.global]` rule - in one of four mandatory CSS cascade layers, lowest to highest priority: `styled-ppx.global`, `styled-ppx.descendant`, `styled-ppx.base` (unconditional), `styled-ppx.conditional` (wrapped in `@media`/`@supports`/`@container`, or carrying a pseudo-class/pseudo-element attached directly to the atom's own selector) - declared via one unconditional `@layer styled-ppx.global, styled-ppx.descendant, styled-ppx.base, styled-ppx.conditional;` statement right after any hoisted `@import`/`@namespace`. `@property`/`@keyframes`/`@font-face` registrations and a literal, user-authored `@layer` at-rule (statement or block form) stay outside all four tiers, exactly where they were before - nesting a user's own `@layer` inside one of these would rescope whatever sub-layer name it declares. This fixes four real bugs stylesheet position alone could not: a block's own `@media`/`:hover` override landing before its unconditional declaration in the deduplicated output (so the unconditional rule always won, even while the condition held); the same atom emitted by two different `styled-ppx.generate` invocations landing in a different order relative to another sheet's conditional override depending only on which `<link>` a page loads last (every sheet now agrees on `global < descendant < base < conditional` regardless of load order, since CSS fixes layer priority by first occurrence across every stylesheet on the page); an ancestor's descendant selector reaching for an unclassed element or `*` (`.wrapper * {color}`, `.wrapper > span {color}`) beating that element's own class on the same property purely by landing later in the stylesheet - a descendant rule whose subject DOES carry its own class (`.wrapper .id-...`, `.wrapper .tiptap`) is unaffected, staying `base`/`conditional` as before, since it targets a specific, identified element rather than "whatever happens to be under here"; checked independent of `@media`/pseudo wrapping, so a conditional ancestor's blind reach still loses to the child's own base rule; and a `[%styled.global]` default (`*{box-sizing:inherit}`, a global `a{color:blue}`) beating an atom on the same element purely because an unlayered normal declaration beats any layered one in CSS regardless of specificity - global rules are now layered too, in their own, lowest layer. A real, documented behavior change: a global selector with HIGHER specificity than an atom (`.theme-dark .card{color}` vs an atom) used to win outright; now layer order beats specificity entirely, so the atom always wins - an author whose global must still win uses `!important`. `!important` on a `styled-ppx.global`/`.descendant` declaration still beats a plain declaration in a higher tier (importance precedes layer order in the CSS cascade, and among `!important` declarations the earliest layer wins) - an intentional escape hatch, not a gap. Inside each tier, a stable sort puts an atom covering more of a property family's leaves (a shorthand, or a wider family atom) before one covering fewer of the same family, reading property names from each rule's own rendered text through `Slot_key.Family`'s shorthand data; this fixes what `CSS.merge` cannot see inside a bundle (two conflicting properties hidden behind one opaque `in-` class) by restoring the correct override through stylesheet position instead. `--layers` (opt-in) now nests its existing per-library `@layer` inside each tier instead of wrapping the whole rule list, so a library still gets exactly one nested block per tier it actually contributes a rule to. Documented, not fixed: `Merge_key`/`Slot_key` recognize an atom by class-name prefix and length alone, so a hand-written author class shaped like a real atom (whose body happens to be exactly the family+value floor length) is indistinguishable from one and can be silently dropped by `CSS.merge` - pinned as current behavior in `packages/runtime/test/test_merge_key.ml`; the `_a_`/`_in_`/`_id_`/`_k_` prefix rename above narrows the odds of an accidental collision but does not eliminate them (@davesnx)

- [BREAKING] Remove the `backdrop-blur` and `container-name-computed` properties. Neither is a real CSS property (no spec defines either name under a shorthand or standalone `property:` grammar; `container-name-computed` looked like a computed-value introspection artifact, not something CSS ever lets an author write), and nothing else in the repository referenced them. A declaration using either name now fails with the usual unknown-property error instead of silently validating (@davesnx)
- [FIX] Hoist `@import` rules, then `@namespace` rules, to the front of `styled-ppx.generate`'s output, regardless of which module or library emitted them, since a browser only honors these rules when they precede every other rule, dependency order routinely places one after plain style rules, and CSS Cascade 5 requires every `@import` to precede every `@namespace`. Statement-form `@layer a, b;` is left where it falls: CSS allows it anywhere in a stylesheet, and hoisting it would change layer order (layer order is first occurrence). Classify by the rendered rule's text (`@import`/`@namespace` prefix, `;` suffix) instead of by the presence of a `{`, since an `@import` URL can itself contain `{`. Drop `@charset` instead, with a warning naming the input file: the generated file always opens with its own leading comment, so `@charset` can never be the literal first bytes of the stylesheet, and the output is UTF-8 regardless (#581) (@davesnx)
- [FEATURE] Mint a build-independent **identity class** (`id-<hash>`) for every named `[%css]` binding and `[%styled.<tag>]` component, derived from the module, submodule scope, and binding name (never a physical path or dune library name), plus an occurrence index when a name repeats within one compilation unit. Same-named `Module.binding`s in two different libraries now share an identity unless `--namespace` differs between them. A `let` named with a `__` prefix, such as the `__incoming` temporary server-reason-react's `styles=` expansion introduces, is not a binding for this purpose: the `[%css]` under it takes the enclosing user binding's name for its label, dev marker and identity. Add PPX flag `--namespace <string>`, mixed into the identity hash so two libraries whose modules share a basename and binding name can be told apart, or a native library and its melange twin can be kept together; the aggregator reports an identity collision, naming both input files, the longident, and the identity, when two different bindings share an identity but not their CSS (@davesnx)
- [BREAKING] `$(binding)` and `&.$(binding)` selector references now resolve to the referenced binding's identity class, one class regardless of how many atoms (or none) it minted, instead of a dot-chain of its atomized classes such as `.cssA.cssB`. A referenced multi-atom binding drops from `(0,N,0)` to `(0,1,0)` specificity inside the compound selector. An empty named binding (`let m = [%css {||}]`) now keeps its identity under `--minify` too, fixing a bug where `&.$(m)` silently lost its qualifier in production (@davesnx)
- [BREAKING] Class names are `a-<hash(content)>` in every mode; the binding's `let` name no longer appears in the class name, so two bindings with byte-identical declarations now mint the same class and dedup to one rule. `--minify` only strips CSS whitespace and no longer affects class names. Dev-mode `label:<binding>` marker classes are now on by default, for `[%css]` bindings and `[%styled.<tag>]` components alike (keyed off the component's module name); `--minify` and `--env production` turn them off, and `--dev` forces them back on regardless (@davesnx)
- [BREAKING] `@keyframes` names are `k-<hash(body)>` instead of `keyframe-<hash(body)>` (@davesnx)
- [FEATURE] Add PPX flag `--env development|production`. `development` enables `--dev` marker classes; `production` enables `--minify` and disables markers (@davesnx)
- [FIX] Parse the Selectors Level 4 `An+B of S` form of `:nth-child()`/`:nth-last-child()` (`:nth-child(2n+1 of .x)`), and functional pseudo-elements such as `::part(foo)` and `::slotted(.bar)`. The lexer only special-cased `nth-*` names for An+B payloads and gave every other identifier followed by `(` a generic function token that `::`-parsing never handled, so both forms hit a raw parse error; the renderer already had support for the "of S" AST shape, just not a parser path to it (@davesnx)
- [FIX] Accept CSS Nesting's relative-selector shorthand in a nested rule's prelude: `.parent { > .child {} }`, `+ .sib {}` and `~ .sib {}` resolve exactly like `& > .child`. The root of `[%css]`, `[%styled.global]` and a raw stylesheet still rejects a leading combinator, and `[%styled.global]` now also rejects one inside an at-rule block with no enclosing style rule (`@media print { > .a {} }`), the same way it rejects a parentless `&`, instead of shipping unresolved `&` (@davesnx)
- [FIX] Report correct error locations for `[%css]`, `[%styled.*]`, `[%styled.global]` and `[%keyframe]` strings in `.ml` files. The ppx always skipped the opening quote or `{id|` to find the string's content, but OCaml's lexer (unlike Reason's) already starts the string's location at the content, so every location in a `.ml` file was shifted right by the delimiter's width: one column for `"..."`, two for `{|...|}`. For example, `[%css "@import 'x.css';"]` pointed past the `@` (@davesnx)
- [FIX] Stop a style rule's selector location from including the whitespace between the selector and what follows it (`{`, `,`, or end of prelude). `&:hover { color: red; }`'s error location for `&:hover` covered `&:hover ` with the trailing space, one character wider than the selector itself (@davesnx)
- [FEATURE] Register the css-fonts-5 metric-override descriptors `ascent-override`, `descent-override`, `line-gap-override` (each `normal | <percentage>`), and `size-adjust` (`<percentage>`), so a valid `@font-face` block declaring them compiles instead of failing with an unknown-descriptor error (#580) (@davesnx)
- [FIX] Reject the `@font-face`-only descriptors (`src`, `unicode-range`, `font-display`, `ascent-override`, `descent-override`, `line-gap-override`, `size-adjust`) in any declaration outside an `@font-face` block. `.title { ascent-override: 90%; }` previously compiled and emitted a descriptor browsers ignore; it now fails with `Descriptor 'ascent-override' is only valid inside @font-face`. The reverse holds too: an `@font-face` body accepts descriptors only, so `@font-face { color: red; }` fails with `Property 'color' is not a @font-face descriptor` (@davesnx)
- [FIX] Lex an escaped identifier into its canonical CSS spelling instead of the decoded text. The lexer decoded `\31 a` to `1a` and dropped the escape, so `.\31 a { color: red; }` (class `1a`) rendered as the invalid `.1a{...}`, and `.a\.b { color: red; }` (one class named `a.b`) rendered as `.a.b{...}` — two classes, changing what the selector matches with no error at all. Every identifier token (class, id, type selector, attribute, pseudo-class, custom property name, custom ident, dimension unit) now re-escapes per CSSOM `serialize an identifier` as it is lexed; a hash that does not start an identifier (`#123456`) is a color and keeps its decoded text (@davesnx)
- [FIX] Parse statement at-rules by what follows their prelude instead of a fixed name list, so `@layer a, b;` and any future statement at-rule work in `[%styled.global]`; the one-token `AT_RULE_STATEMENT` is gone. Trailing whitespace in a statement prelude is trimmed, so `@import "x.css" ;` renders as `@import "x.css";` (@davesnx)
- [FIX] Make `clamp()` and `env()` reachable from `<length>` and `<percentage>` values (`width: clamp(10px, 5vw, 100px)`, `padding-top: env(safe-area-inset-top)`), not just registered as standalone functions. `Extended_length`/`Extended_percentage` enumerated `calc()`/`min()`/`max()` but omitted their peers, rejecting every property built on them; extend `Extended_angle`, `Extended_time`, `Extended_time_no_interp`, and `Extended_frequency` with `clamp()` too for the same reason. Also fix `env()`'s own grammar, which required a literal `,` even with no fallback value, rejecting the common `env(name)` form used by every real safe-area-inset call (@davesnx)
- [FIX] Accept `var(--x,)` and `var(--x, )`, an explicitly empty fallback, which css-variables-1 defines as a valid, meaningful zero-length value distinct from omitting the fallback entirely (`var(--x)`). `var()`'s fallback grammar wrapped the comma and `<declaration-value>` in one optional group, and `<declaration-value>` itself requires at least one token, so an empty fallback made the whole group's atomic match fail and left the comma unconsumed, rejecting the value outright; a fallback with a comma inside it (`var(--x, a, b)`) was unaffected. The comma is now its own required token once a fallback is present, wrapping only `<declaration-value>` as independently optional, so an empty fallback renders back out with the comma preserved (@davesnx)
- [FIX] Lex a signed number whose sign is directly followed by a decimal point, with no leading digit (`-.5px`, `+.5s`), instead of crashing the whole PPX with an uncaught `Failure("float_of_string")`. `consume_number` only matched a sign together with at least one following digit, so it consumed nothing for this spelling and produced an empty number representation (@davesnx)
- [FIX] The parser drops leading and trailing whitespace from a declaration's value, so the renderer, the autoprefixer and the validator all see the same value. A declaration terminated by `}` or end of input with a source-level space before the terminator (`{ display: flex }`) now renders and hashes identically to the same declaration terminated by `;` (`{ display: flex; }`); previously the two rendered as `display:flex;` and `display:flex ;`, minting distinct classes for byte-identical CSS. The autoprefixer no longer skips the `-webkit-grab` / `fit-content` prefixes for such a value, and a css-wide keyword no longer bypasses the property-name check (`colr:inherit;` is now an error) (@davesnx)
- [BREAKING] Remove `--minify` from `styled-ppx.generate`. Move the setting to the PPX stanza, for example `(pps styled-ppx --env production ...)`. The PPX records the environment in each compiled file; the generator minifies only when every input declares production and warns when environments are mixed (@davesnx)
