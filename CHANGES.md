# Changes

## 0.62.0

- [BREAKING] `styled-ppx.generate` orders style rules as one "ordered sheet", with no CSS layer: `[%styled.global]` rules first, in source and dependency order, then every atom rule in one topological order. The ppx computes each atom rule's sort key from the AST and writes it next to the rule, `[@@@css (text, class, scope, family, mask, descendant)]` (a global rule, `@keyframes` or `@property` stays `[@@@css "text"]`); generate reads only this payload and no longer parses rule text, so an attribute selector with `~=` or a quoted space, or a `-webkit-` copy of a declaration, no longer distorts the order. Two atom rules compete when their scope (importance, specificity, the element and pseudo-element they style) is equal and they set a shared longhand, a legacy alias such as `grid-gap` read as its canonical property `gap`. Competing rules are ordered by, in priority: descendant-shaped rules first; block edges, from `[@@@css.blocks [(line, identity, [rule index; ...]); ...]]`, which lists every `[%css]`/`[%styled.<tag>]` block, named or anonymous, with its rules in emotion order (the block's own declarations, then its nested rules, each in source order, and the same inside each nested rule), so `@media (max-width: 600px) { color: pink; } color: black;` gives pink under the media query, `padding: 8px; @media (min-width: 768px) { padding: 16px; } padding-top: 0;` gives 16px at 768px and wider, and `&:focus { color: blue; } &:hover { color: red; }` gives red; merge edges, from `[@@@css.merges [(line, [operand; ...]); ...]]`, which lists every `CSS.merge(a, b)` and `a +++ b` whose arguments the ppx resolves (a `[%css]` binding of the same file or of another module, or an inline `[%css]`), so `a`'s competing rules come before `b`'s whichever block defined a shared atom first, leaving out a class the merge drops at run time; then definition order. The class list `CSS.make` receives follows the same emotion order. Two blocks or merges that order one pair in opposite directions get a build warning that names both, and the pair keeps definition order; a longer cycle is cut at one rule with a warning. `!important` needs no special case: importance is compared before specificity and position. Limits: a merge argument the ppx can not resolve (a function call, a parameter) adds no edge, and definition order decides; two separate `styled-ppx.generate` runs (two `<link>`s) have no relative order between the rules they share. Documented in `documents/css-extraction.md` ("Wire protocol", "Sheet order") and `documents/how-merging-works.md` ("Sheet order", "Known limits") (@davesnx)
- [FIX] The mask field of an atom class is 4 base36 chars instead of 3. A family mask is one bit per longhand, and `font` (20 longhands) and `border` (17) did not fit in 3 chars, so the mask wrapped and read as the bits of other longhands: `CSS.merge(%css "font-style: italic;", %css "line-height: 1.5;")` dropped `font-style`, and `border-image-source` was dropped by a later `border-top-width`. Atoms with a mask (longhands) get one more character, and class names change (@davesnx)
- [BREAKING] Add `` `clamp of t * t * t `` to the runtime `Length` type (native and Melange share it): `let size = `clamp(`rem(1.), `vw(2.), `rem(3.)); [%css {|width: $(size)|}]` renders `clamp(1rem, 2vw, 3rem)`. Exactly 3 arguments, matching the `clamp()` grammar already in the parser; like `min`/`max`, the `none` keyword css-values-4 allows for the first and last argument is not modelled. A `switch` on a length type that lists every constructor and has no `_` case must add a `` `clamp(a, b, c) `` case (@davesnx, idea from @Atlas07 in #579)
- [FEATURE] Validate the preludes of `@media`, `@supports` and `@container` at compile time, so `@media (min-widht: 1px)`, `@media (width: 10)` or a malformed `@supports`/`@container` condition is an error with a location and, for feature-name typos, a `Did you mean` suggestion. Feature values (`<length>`, `<ratio>`, `<resolution>`, `<integer>`, keyword sets, and the operands of range forms such as `(400px <= width <= 900px)`) are checked against per-feature grammars; `@supports` is exempt from name checks. `@container` size features now accept their `min-`/`max-` spellings (`min-width`, `max-inline-size`, ...), and `resolution` accepts `infinite`. Interpolated preludes are not validated. (@davesnx)
- [FEATURE] The parser accepts CDO/CDC tokens (`<!--`, `-->`) at the top level of a stylesheet and ignores them, as CSS Syntax Level 3 §5.4.1 specifies. They stay a parse error inside blocks (@davesnx)
- [FEATURE] The parser accepts namespace prefixes in type and attribute selectors (`svg|circle`, `*|a`, `|a`, `svg|*`, `[xlink|href]`), per Selectors Level 4 `<wq-name>` and `<ns-prefix>`. `[lang|=en]` keeps its meaning. - [FIX] Inside one `[%css]`/`[%styled.*]` block, when 2+ `@media` rules set the same property (or overlapping shorthand family) on the same selector, each earlier condition is now rewritten to exclude every later one (StyleX's `lastMediaQueryWinsTransform`) before the rule is hashed into a class, so the LAST written `@media` rule always wins regardless of stylesheet position: `@media (min-width: 600px) { color: red } @media (min-width: 900px) { color: blue }` now extracts as `@media (min-width: 600px) and (not (min-width: 900px)) { color: red } @media (min-width: 900px) { color: blue }`. The negation is always wrapped in its own parentheses (`(not (...))`): Media Queries 4 allows a bare `not` only at the start of a whole condition, and browsers parse `(a) and not (b)` as `not all`. A comma-separated (`or`) condition is negated by De Morgan into every branch independently; a 3+-way group chains against every strictly later member, not just its immediate neighbor. This also fixes a real cross-block bug: two blocks writing the same two `@media` rules in opposite source order used to mint byte-identical atoms that collided under `styled-ppx.generate`'s first-sighted dedup, silently giving both blocks whichever order the aggregator saw first; each block's atoms now carry their own negated condition and no longer collide. `@media` only, matching StyleX exactly - `@supports` and `@container` are a known, deliberate gap. v1 always wraps, even when the two ranges are already disjoint (the common case) - no interval/range math yet, so a correct, non-overlapping pair costs a redundant `and (not (...))` clause in bytes only. A `@media` block whose content doesn't reduce to one clean (selector, property family) unit - further nesting, or two unrelated properties in one block - is left untouched rather than guessed at. A group is negated only when every negated (later) feature test resolves to a definite true/false in every browser - `min-width`/`max-width`/`min-height`/`max-height` with a literal px/em/rem length, or `orientation` - never `calc()`, a percentage, or range-comparison syntax: negating a feature the browser cannot evaluate (for example `calc()` mixing an absolute length with a percentage) makes the earlier rule never apply, so its value would be lost. A query carrying a media type (`screen and (...)`, `not screen`, or a comma list mixing a type with a plain condition) is left untouched too, EXCEPT when every member of the group shares the exact same bare-or-`only` type (`screen`/`only screen`, the common real shape): the shared type is carried through unchanged and only each member's own feature chain is negated, e.g. `@media screen and (max-width: 992px) {...} @media screen and (max-width: 480px) {...}` extracts the first as `@media screen and (max-width: 992px) and (not (max-width: 480px)) {...}`. A `not`-prefixed type (`not screen and (...)`) stays a known gap even with an otherwise-matching type on every member: `not` inverts the whole query (type and condition together), so folding a negation into just the condition gives a wrong result. `CSS.merge` still compares the condition as written, not the rewritten one, so a rewrite in one block never changes what `CSS.merge` drops (@davesnx)

- [BREAKING] A block's interpolating declarations now bundle into one shared class only when they interpolate the SAME `$(name)` source path (transitively, same union-find technique the leaf-overlap grouping already uses for shorthands), instead of whenever two or more of them merely both happen to interpolate. `color: $(a); background-color: $(b);` used to force `a` and `b` into one opaque `_in_` bundle for no reason neither value needed; both now mint their own real, slot-keyed `_a_` class and `CSS.merge` resolves each independently. `$(a)` used twice in one block - base and `:hover`, or any other combination of variants - still shares exactly one variable and one inline custom property, same as before: the invariant bundling exists for is unchanged, only narrowed to declarations that actually need it. A declaration whose path no sibling shares still joins the existing leaf-overlap grouping with its block's other declarations first, unaffected - this only changes which SINGLETON interpolating atoms end up sharing a class (@davesnx)
- [BREAKING] Generated names use underscore-delimited prefixes: atom classes `_a_…`, interpolation bundles `_in_…`, identity classes `_id_…` and `@keyframes` names `_k_…` (was `keyframe-<hash>`). `CSS.merge` reads only `_a_` tokens as atoms, so a hand-written class such as `a-header` is never mistaken for one; a hand-written class that starts with `_a_` and has one of the six atom lengths still can be. Code or CSS that hard-codes a generated class or keyframe name must follow (@davesnx)
- [BREAKING] A block with TWO OR MORE declarations that carry a `$(...)` value interpolation now mints one shared `_in_<hash>` class for all of them instead of `_a_<hash>` per declaration (same murmur2 digest of their concatenated content, only the prefix changes; the `var(--...)` custom-property name each one sets is unaffected). A block with exactly ONE interpolating declaration is unaffected by this bundling and keeps its own real, slot-keyed `_a_` class (see below). `CSS.merge` (below) recognizes an interpolation-bundled atom this way - several different declarations from one binding legitimately sharing one class, by design - and never drops it or lets it drop another atom, and `styled-ppx.generate`'s atom-class collision check (below) skips it, since two different bundle bodies sharing a class is not a collision (@davesnx)
- [FEATURE] `styled-ppx.generate` now errors when two different, non-bundle atoms (`_a_` classes) mint the same class name but render different CSS - a value-hash collision - the same way it already errors on a `_id_` identity collision. `_in_` (interpolation-bundle) classes are exempt: sharing one class across different bundle bodies is expected there, not a collision (@davesnx)
- [BREAKING] Two declarations in one block now mint ONE atom, declarations in author order, when their covered leaf properties overlap - taken transitively - instead of one atom per declaration. `margin: 10px; margin-top: 0;` is one atom (margin's full leaf set includes margin-top), so the final declaration in a mixed shorthand/longhand group reliably resets the earlier ones by source order, not by where two independently-hashed atoms happen to land in the generated stylesheet. This extends the existing same-property grouping (`display: -webkit-box; display: flex` already grouped into one atom, a same-property repeat overlapping itself trivially). Sharing a property family alone is not enough: `padding-left: 0; padding-right: 0;` stay two atoms, since padding-left and padding-right cover disjoint leaves - merging them would make `CSS.merge` (below) unable to drop just the overlapping side. A legacy alias counts as its canonical property, so `row-gap: 2px; grid-row-gap: 1px;` is one atom (@davesnx)
- [BREAKING] Non-bundle class names are now `_a_<context?><family><mask?><value>`: a fixed-width context hash (present only under a real selector/at-rule, or when the declaration carries `!important`), a 2-character property-family id from a fixed table, an optional mask of which of the family's longhands the atom covers, and a value hash unique only within that (context, family[, mask]) bucket, not globally - shorter than the previous plain content hash for the common case. This is what `CSS.merge` (below) parses at runtime to decide which classes to drop, with no shorthand table (@davesnx)
- [FIX] `Slot_key.family_id_of` now prefers a family's already-registered shorthand member over `Family`'s shortest-name rule when picking the family's class-name id. Without this, a shorthand registered later that unions with an existing family (e.g. a `rule` shorthand covering `column-rule`/`row-rule`) could win the family's id for being shorter, silently renaming every existing atom of the older member (e.g. `column-rule`) with no error. Ties still fall back to the shortest-name rule, but only when no member of the family has a table slot yet. Pinned by a new invariant test over every registered shorthand in the id table (@davesnx)
- [FEATURE] `CSS.merge(a, b)` (native and melange) now drops a class of `a` when a class of `b` covers the same slot - same context, same property family, `a`'s longhands a subset of `b`'s - instead of concatenating both class strings unconditionally. This fixes a real bug: under content-hash dedup, an atom two components both use can be minted first by either one, and the browser's cascade then picks whichever copy's rule landed first in the generated stylesheet - independent of which `CSS.merge` call actually meant to win. `!important` needs no separate check (it is folded into the context, so a plain declaration and its `!important` twin never remove each other); a bundle, an identity class, a `label:<binding>` marker, and any class this pipeline didn't mint are never dropped and never drop anything else. Accepted limit, pinned by tests: `merge(shorthand, one-of-its-own-longhands)` keeps both classes, since a lone longhand's mask is never a superset of the shorthand's full mask - which one wins still depends on stylesheet position in that one direction (@davesnx)
- [FIX] Resolve a `[%css]` selector's `$(binding)`/`&.$(binding)` reference to the referenced binding's identity class BEFORE atomizing, not after. An atom's class name and `Slot_key` context both hash the rendered selector text; hashing it before resolution left the literal `$(binding)` marker in that text, so two files using the same local binding name in the same selector shape (e.g. `& > div:not(:last-child).$(row)`, with each file's own, differently-defined `row`) minted the SAME atom class even though `row` resolves to a different `_id_` class per file - a real collision `styled-ppx.generate`'s atom-class collision check (above) then correctly rejected. A same-reference case (two files, or a cross-module `$(Module.binding)`, naming the exact same binding) still dedups to one class, unaffected (@davesnx)
- [FIX] A block with exactly ONE `$(...)`-interpolating declaration no longer bundles: it mints its own real, slot-keyed `_a_` class - same path a static atom uses - so `CSS.merge` (above) can resolve it like any other atom instead of treating it as an opaque, always-kept `_in_` blob. Bundling still applies, unchanged, to a block with two or more interpolating declarations (typically the same value reused across `base`/`:hover`/`@media` variants, which still needs one shared custom-property namespace). This fixes two real cases `CSS.merge` previously couldn't touch: two same-property, single-declaration interpolated overrides (e.g. `background-color: $(accent)` vs `background-color: $(bg)`), and a single interpolated declaration overridden by a later static one of the same property (e.g. `padding-top: $(gap)` vs a later `padding-top: 0`) - both used to keep both classes and depend on stylesheet position; both now resolve by merge-call argument order like any other atom. `Slot_key.t.bundle` no longer self-detects from a declaration's own interpolation (a per-atom fact it could get wrong, since bundle-hood depends on how many OTHER declarations share the block); it is always `false` from `Slot_key.of_atom` now, since a genuine bundle's class is minted directly and never goes through `Slot_key`/`Class_format.slot_class` (@davesnx)

- [FIX] Hoist `@import` rules, then `@namespace` rules, to the front of `styled-ppx.generate`'s output, regardless of which module or library emitted them, since a browser only honors these rules when they precede every other rule, dependency order routinely places one after plain style rules, and CSS Cascade 5 requires every `@import` to precede every `@namespace`.
